# rmedia 0.2.0-dev — Unreleased (feature 002, user stories 1 to 3)

**Status:** Development notes, not a release. Work is on branch `002-mobile-upscale`. The
workspace version is still `0.1.0`; no `0.2.0` version bump, tag or package exists. User stories
1 to 3 of feature 002 are implemented (73 of 112 tasks). Stories 4 to 6 are planned and are not
available; see the [Roadmap](../roadmap.md).

## Summary

`rmedia upscale` makes videos phone-ready: it scales and reframes each video to the screen size
of a device preset, re-encodes it, and verifies the result. It runs on the CPU tier, or on the
GPU tier when the machine has a usable Vulkan GPU that is not slower than the CPU.

## New Features

- **`rmedia upscale`** — `rmedia upscale INPUT... [OPTIONS]` processes each video whole, one job
  per video. Inputs can be files, folders (scanned with the same options as `scan`) or
  `--inputs-from FILE|-`. Outputs go to an `upscaled/` folder next to each source and are named
  `{source}_{preset}.mp4`. Upscaling always re-encodes, so `--mode` does not exist for this
  command. See the [CLI Reference](../api/cli-reference.md#rmedia-upscale).
- **Device presets** — seven built-in presets: `phone-fill` (1080x2340, the default),
  `phone-fill-hd`, `pixel-tall`, `reddit-916`, `reddit-feed-45`, `fold-inner` and `duo`.
  `rmedia upscale --list-presets [--json]` lists them, plus presets you add as JSON files in the
  `presets` folder of the config directory. Invalid preset files are reported and ignored.
- **Reframing** — `--reframe center` crops the centre of the frame; `--reframe blur` shows the
  whole frame over a blurred background. `--reframe smart` (the default) follows faces: shots are
  detected, the crop pans smoothly within a speed limit (`--motion calm|normal|fast`) and jumps
  only at cuts; parts where no face fits use the blurred background and are listed in the plan and
  the job result. A dry run shows the shots and blurred ranges; `--crop-path FILE` writes the
  per-frame crop path. The analysis is cached under the cache folder (`RMEDIA_CACHE_DIR`).
- **HDR handling** — HDR sources are converted to standard range by default (`--hdr sdr`).
  `--hdr keep` keeps HDR for presets that support it; HDR mastering metadata is not carried over.
- **GPU tier and machine check** — the GPU tier scales with libplacebo on a Vulkan GPU (the
  device is pinned, software renderers such as llvmpipe are never used) and matches the CPU
  tier's quality (57.66 against 57.63 VMAF on the 480p fixture). rmedia checks the machine once
  per hardware, driver, engine or app change: it lists the GPUs and times a short CPU and GPU
  self-test that includes the encoder. `--tier auto` (the default) takes the GPU tier only when
  its self-test is at least as fast as the CPU's; the dry run says which tier and why. If an
  automatic GPU job fails it is retried once on the CPU with a warning, and the GPU is not chosen
  again until the next check. `--tier gpu` forces the GPU and never falls back.
- **Estimates and limits** — dry runs show the estimated output size and time. They warn when a
  preset's platform limit (size or duration) would be exceeded, and when an output folder has less
  free space than the outputs need (with a 20% margin).
- **Verification and cancel** — every output is probed before it is kept. Ctrl-C stops an upscale
  within about 2 seconds and leaves no partial file, scratch folder or engine process behind.
- **Richer diagnostics** — `rmedia doctor` now lists `libx265` among the encoders, prints a
  `filters:` line, and adds `tier:`, `gpu:`, `model:` and `checked:` lines from the machine
  check. `rmedia doctor --recheck` measures again. `doctor --json` adds `filters`, `tiers`,
  `gpus`, `models`, `capability` and `preset_problems`. The desktop Settings dialog shows the
  tiers and has a **Check again** button.
- **Model download task** — `cargo xtask fetch-models` downloads the pinned model files into
  `models/` and verifies their SHA-256. The face detector it fetches is used by smart reframe.

## Enhancements

- `--json` run events add a `job_stage` event (upscale jobs only) that names the stage the job is
  in. `job_progress.fraction` covers the whole job.
- Succeeded outcomes carry a `measure` key (`clip` or `upscale`). For clip jobs this is the only
  change; `actual` and `adjusted` are unchanged.
- Plan JSON for upscale jobs adds `kind: "upscale"` and an `upscale` block with `reframe_applied`.
  Clip jobs keep their 001 shape. See [JSON Output](../api/json-output.md).
- New environment variable `RMEDIA_CACHE_DIR` replaces the cache root. See
  [Configuration](../administration/configuration.md#environment-variables).
- New issue codes: `TIER_UNAVAILABLE`, `PRESET_UNKNOWN`, `HDR_UNSUPPORTED` (errors) and
  `LIMIT_EXCEEDED` (warning).

## Breaking Changes

None for clip workflows. Consumers of `--json` output should ignore keys they do not recognise.

## Behaviour to Know About

- The first `upscale` or `doctor` after a hardware, driver, engine or app change takes a few
  seconds longer while the machine check runs; later runs reuse it (about 0.1 s). `--tier cpu`
  skips it.
- On the reference laptop's integrated GPU the GPU tier measured slower than the CPU (the encoder
  dominates both), so `auto` stays on the CPU there. Use `--tier gpu` to force it.
- `--tier ai` stops with `the ai tier is not available on this machine: the AI tier is not built
  yet` (exit 3, `TIER_UNAVAILABLE`). A forced `--tier gpu` without a usable GPU stops the same way.
- GPU-tier output may differ slightly between GPUs and drivers; the CPU tier is byte-identical.
- Smart reframe needs the YuNet face model (`cargo xtask fetch-models` in a checkout); without it
  rmedia uses the blurred background with a warning. It pans horizontally only.
- Videos that mix tracked and blurred sections render both pictures for the whole clip, so they
  take longer than `center` or `blur`.
- `--container` for upscale accepts only `mp4`; another value is ignored with the warning `upscaled outputs are always .mp4`.
- `rmedia batch` and `rmedia clip` cannot upscale yet (`clip --upscale` and manifest upscale
  fields are user story 4). The desktop app has no upscale view yet (user story 5).
- The CPU tier is deterministic: the same inputs, options and engine give identical bytes on one
  machine.

## Known Issues

| Issue | Effect |
|---|---|
| `--hdr keep` carries no HDR mastering metadata | A warning says so |
| A symlinked `upscaled/` folder that already exists is followed | Output names are run-specific, so nothing is overwritten through the link |
| Rare colour tags (smpte240m, film) use BT.601 or BT.709 defaults | Colours of such sources may differ slightly |
| Very long source names can exceed 255 bytes in temporary file names | The job can fail on such names |
| `cargo deny` advisory for `proc-macro-error` via Tauri's GTK dependencies | Predates 002; development tooling only |
| On Windows, a GPU driver update registered only under the display-adapter key is not noticed | Run `rmedia doctor --recheck` after updating the driver |

## Validation Status

- 244 tests pass, 6 ignored (108 at the 001 baseline). The GPU-tier tests skip on machines without a usable Vulkan GPU.
- On synthetic fixtures the CPU tier beats bicubic scaling by +2.78 VMAF (480p) and +2.89 VMAF
  (360p); the agreed bar is +1.5. A 60 s 480p30 clip upscaled to 1080x2340 in 101.5 s (bar 120 s).
- Owner checks still open: two-phone gallery test, Reddit test upload, +3 VMAF on real footage.
