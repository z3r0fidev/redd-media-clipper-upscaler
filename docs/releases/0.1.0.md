# rmedia 0.1.0 — Unreleased (feature 001 "Video Clipping Base")

**Status:** Release candidate. The workspace version is `0.1.0` (`Cargo.toml`, `tauri.conf.json`),
and validation is recorded on 2026-10-06 (`specs/001-video-clipping/checklists/validation.md`).
No `v0.1.0` git tag exists yet. Pushing a `v*` tag runs `.github/workflows/release.yml`, which
builds installers; publishing and signing are separate manual steps. Release date: to be decided.

Commit range: `c514bb9` … `bd1eef8` (10 commits).

## Summary

This is the first release of rmedia. It cuts clips from videos on Linux and Windows, from the
command line or a desktop app. Fast mode cuts without re-encoding; accurate mode re-encodes
frame-exactly. Source files are never modified.

## New Features

- **Single clips from timestamps** — `rmedia clip VIDEO -s START [-e END | -d DURATION]`. Times
  accept `90`, `1:30`, `00:01:30.500`, `00:01:30,500` and `1m30s`; durations accept `+15`; and
  `end` means the end of the video. All requests are validated before anything runs.
- **Fast and accurate modes** — Fast mode (the default) stream-copies and starts on the keyframe
  at or before your start time, then tells you how early it started. Accurate mode re-encodes
  (H.264/AAC, or VP9/Opus for WebM) and is frame-exact, including for MPEG-TS and mislabelled
  files. Each accurate clip's length is verified before it is kept.
- **Clip lists** — `-l highlights.txt` with one clip per line (`START END|+DURATION [NAME]`), `#`
  comments and decimal commas. Every bad line is reported with its line number before processing.
- **Batch manifests** — `rmedia batch jobs.json|jobs.csv` runs many videos × many clips. Defaults
  can be set per manifest, per video and per clip. Equivalent JSON and CSV manifests produce
  identical jobs.
- **Folder discovery** — `rmedia scan` finds real videos recursively. It skips non-videos, cover
  art, still images, partial downloads, hidden and system folders, symlinks (by default) and, on
  Windows, online-only cloud files. `clip` accepts folders and `--inputs-from FILE|-`, and never
  re-clips its own output folders.
- **Desktop app (Tauri 2 + Svelte 5)** — add files or folders (picker, drag-and-drop or command
  line), preview with in/out marking (`I`/`O`/`Enter`, frame stepping), edit the queue as text,
  import clip lists and manifests, export the queue as a manifest, and watch per-job and overall
  progress with cancel. Formats the webview cannot play are previewed through a 480p proxy or
  exact still frames. Clips are always cut from the original.
- **Same results from CLI and app** — the app's queue is a batch manifest. Running the exported
  queue with `rmedia batch` produces byte-identical clips (SC-008, tested).
- **Scriptable CLI** — `--dry-run`, `--json` (NDJSON run events, plan, scan and doctor documents),
  stable error codes and exit codes (0, 1, 2, 3, 4, 130). See the
  [CLI Reference](../api/cli-reference.md) and [JSON Output](../api/json-output.md).
- **Diagnostics** — `rmedia doctor` and **Settings › Video engine** report the engine in use, its
  version, key encoders and the containers accurate mode can write.
- **Bundled engine** — installers include the `rmedia` CLI and a pinned FFmpeg build installed as
  `rmedia-ffmpeg` / `rmedia-ffprobe`, so they never conflict with a system FFmpeg. Packages:
  `.deb` and AppImage (Linux), NSIS setup and MSI (Windows), and standalone CLI archives.

## Behaviour to Know About

- **Default output location:** a `clips` folder next to each source, named
  `{source}_{index:03}_{name-or-range}.{ext}`. With several sources and `-o`, each source gets
  its own sub-folder.
- **Existing outputs are skipped** by default. `--on-exists rename` picks `name_1.ext`, …;
  `--on-exists overwrite` replaces.
- **Cancellation:** Ctrl-C cancels cleanly and still prints the summary; press it twice to quit
  at once. No temporary files or background processes are left. A crash or kill is cleaned up on
  the next run.
- **Accurate mode into AVI, WMV, FLV, MPEG-PS, 3GP or OGV** writes MP4 with a warning.
  High-bit-depth/HDR sources are written as 8-bit 4:2:0 in accurate mode; use fast mode to keep
  them.
- **Subtitles** are copied to MKV, converted to `mov_text` (MP4/MOV) or WebVTT (WebM) when
  text-based, and otherwise dropped with a warning. In accurate mode on non-indexed sources
  (MPEG-TS and similar), subtitles are dropped.

## Bug Fixes (found during validation and review)

- **Windows:** committing a clip would have failed every time with "Access is denied", because
  the temp file was flushed through a read-only handle. Not yet run on Windows hardware.
- **Windows:** paths shown to users and written to manifests no longer carry a `\\?\` prefix.
- **AppImage:** videos can now play in the app; GStreamer is bundled (`bundleMediaFramework`).
- **Desktop:** the player no longer reloads in a loop when falling back to still frames.
- **Manifests:** in JSON, `"end": "+10"` now means a duration, matching CSV and the CLI.
- **Folder inputs:** a video reached twice (as a file and inside a folder) is clipped once,
  instead of failing with a name-collision error.
- **Desktop export:** a `.json` export now includes the app's **Settings** defaults (mode, output
  folder, file names, if-exists policy) in the manifest `defaults`, with queue values winning, so
  `rmedia batch` reproduces the app's run. (Fixed after `bd1eef8`.)
- **Desktop settings:** the default output folder saved in **Settings** is usable again after a
  restart. A new output folder is accepted only if it was picked with **Choose…**. (Fixed after
  `bd1eef8`.)

## Security Changes

All of these shipped as part of the first release; see the [Security Model](../security/security-model.md).

- Engine programs run with argument vectors only, paths are passed as `file:<path>`, and inputs
  are restricted to local files (`-protocol_whitelist file,pipe`).
- Outputs use unpredictable temp names and an atomic no-clobber commit. The crash journal deletes
  only rmedia's own temp files and never follows symlinks.
- Desktop: the page has only event-listen capabilities. It can use only files the user chose, can
  write clips only inside chosen folders or next to the source, and cannot choose the engine
  executable.
- Desktop playback runs through a loopback-only media server with a per-launch secret token,
  opaque ids, Host/Origin checks and strict ranges.

## Breaking Changes

None. This is the first release.

## Configuration

- Desktop settings: `settings.json` in the per-user config folder (engine paths, default options,
  concurrency, proxy cache size, default 5,120 MB).
- Environment variables: `RMEDIA_FFMPEG` and `RMEDIA_FFPROBE` (engine override);
  `RMEDIA_STATE_DIR` and `RMEDIA_CONFIG_DIR` (used by tests to redirect the state and config
  folders).
