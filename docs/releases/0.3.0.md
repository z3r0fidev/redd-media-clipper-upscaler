## Summary

`rmedia gif` turns a video, a clip or part of one into an animated GIF that looks clean and fits
a Reddit size budget, or into a silent looping "Reddit MP4", which is usually five or more times
smaller. The same export is available from `clip --gif`, `batch --gif`, manifests and a new
**GIF for Reddit** view in the desktop app, with the size estimated from short samples before the GIF is made.

## New Features

- **`rmedia gif`** — `rmedia gif INPUT... [OPTIONS]`, one job per input over `-s/-e/-d`. Outputs
  go to a `gifs/` folder next to each source, named `{source}_{target}.gif` (with the clip number
  and range added when `-s/-e/-d` select part of the video). Dry runs sample the
  input and predict the size (`--no-sample` skips that). See the
  [CLI Reference](../api/cli-reference.md#rmedia-gif).
- **GIF targets as data** — `reddit-post` (8 MB aim, 20 MB limit, the default), `reddit-comment`
  (3 MB / 8 MB), `max-quality` and `flat-ui` (text and screen recordings), plus user targets in
  `<config>/gif-targets/*.json` (schema 1). `rmedia gif --list-targets [--json]`.
- **Built-in engine** — ffmpeg's two-pass palette (palette from the final-size pixels, lanczos
  downscale, ordered or error-diffusion dither, changed-rectangle encoding). Frame rates are
  capped at 50 fps; 10, 20, 25 and 50 fps are exact, others average out with a note.
- **Size-budget search** — a bounded, deterministic search over sample encodes (at most 9
  encodes) lowers the least visible settings first: gifsicle lossy, dither, colours, frame rate,
  then width. The summary and JSON outcome list every step. A budget that cannot be met fails
  with `BUDGET_UNREACHABLE` and the seconds that fit; `--allow-trim` keeps that part.
- **Reddit MP4** — `--format mp4`: silent, fast-start H.264 at the source's rate (by default at
  most the target's `mp4.max_fps`: 60 fps for `reddit-post` and `max-quality`, 30 for the others),
  with a CRF ladder before any width drop. A `reddit-post` dry run says how big the MP4 would be.
- **Bundled engines** — gifsicle 1.98 (post-pass `-O2`, `--lossy`; `reddit-post` uses lossy 10,
  and gifsicle's file is kept only when it is smaller) and gifski 1.34.0 (best-quality GIFs, used
  by `max-quality`), built from pinned sources and bundled as `rmedia-gifsicle` /
  `rmedia-gifski`. Without them everything still works (`ENGINE_FALLBACK`; `--strict-engine`
  makes a missing engine an error). `doctor` lists both.
- **Portrait and square GIFs** — `--shape 9:16|4:5|1:1` with `--framing smart|center|blur`,
  reusing 002's face-following reframe and its analysis cache. A GIF is never enlarged.
- **Clip, batch and manifests** — `clip --gif` (also with `-l`), `batch --gif`, a JSON `gif`
  block layered like `upscale`, and `gif_*` CSV columns. `clip --gif --upscale` is one job with
  no intermediate file. See [File Formats › GIFs in Manifests](../api/file-formats.md#gifs-in-manifests).
- **Desktop "GIF for Reddit" view** — target, format, shape and framing, with **More settings**
  for the rest. The estimated size appears before encoding; **Export now** writes the GIF and plays
  it in the result card. Queue and manifest export give the same files as `rmedia batch`.
- **Several audio tracks in the desktop queue** — a source with more than one audio track shows
  an **Audio tracks** tick box per track; the choice is kept in exported manifests
  (`"audio": [1]`).

## Enhancements

- `exec/pipeline.rs` runs any number of stages joined by pipes (refactor B3): the AI tier and
  ffmpeg → gifski share one kill-tree process model.
- `Error::EngineFailed` names the tool that failed.
- Ctrl-C: `clip`, `upscale`, `gif` and `batch` catch it from the moment they start. Pressed
  while the engine is located, folders are scanned or jobs are planned, it exits 130 with nothing
  written, and `--json` still ends with a `summary` line (without jobs). Before, the process died
  by the signal there, or ignored the press between some steps.
- Logging: warnings from the core (for example `crash journal unavailable`, a reframe analysis
  that could not be cached, a GPU preview that fell back to the CPU) were silently dropped. The CLI
  now prints them on stderr as `warning: …` (`-v` adds `info:`, `-q` hides them, `RMEDIA_LOG`
  overrides), never on `--json` stdout. Each job warning prints once. The desktop app writes them
  to `logs/desktop.log` in the state folder (private to the user, at most about 2 MiB)
  ([Configuration › Logging](../administration/configuration.md#logging)).
- JSON output: `kind: "gif"` jobs, `measure: "gif"` outcomes, and the codes `TARGET_UNKNOWN`,
  `BUDGET_UNREACHABLE`, `OVER_RECOMMENDED`, `ENGINE_FALLBACK`, `TIMING_APPROXIMATE` and
  `LONG_RANGE`; `ENGINE_MISSING` also covers `--strict-engine` ([JSON Output](../api/json-output.md)).
- Settings: `gifsicle_path`, `gifski_path` (also read by the CLI; set in the desktop app only
  through **Settings › GIF export › Choose…**, never by the page) and `gif_defaults`; environment `RMEDIA_GIFSICLE` / `RMEDIA_GIFSKI`
  ([Configuration](../administration/configuration.md)).

## Fixes

- **Windows: no Visual C++ runtime needed.** The Windows binaries link the C runtime statically,
  and ncnn is built without OpenMP, so the AI worker starts without the Visual C++
  Redistributable (0.2.0's known issue).
- **Portrait videos in the desktop player** are shown whole and centred. Before, a tall video was
  pushed down and cut off at the bottom.
- **An invalid `settings.json`** is kept as `settings.invalid-<time>.json` instead of being
  overwritten with the defaults.
- **A sub-second blurred-background range** in a reframe plan shows tenths (`00:54.6–00:55.4`),
  not `00:55–00:55`.

## Breaking Changes

None in behaviour: clip and upscale outputs, their JSON and their exit codes are unchanged. The
licence has changed; see [Licence](#licence).

## Known Issues

| Issue | Effect |
|---|---|
| Reddit's limits (8/20 MB posts, 3/8 MB comments) are **unverified** | They are estimates; check Reddit's Help Center and set `--budget`/`--hard-limit`. A real Reddit upload has not been made yet |
| gifsicle's saving is modest (SC-009) | reddit-post's lossy is 10, so gifsicle costs at most 0.67 VMAF on real footage; it saves 8.1% there (the same on Linux and Windows) and 5.2% on the synthetic set. A higher `--lossy` saves more and costs more quality |
| The packages are unsigned | Windows SmartScreen may warn on first run. Code signing (Azure Artifact Signing) is planned |
| The GIF view is checked by hand on Linux X11 and Windows 11 only | Wayland is untested by hand |
| A dry run with sampling runs ffmpeg (and gifsicle) on the input | `--no-sample` avoids it |
| The AI worker's speed with the static runtime is unmeasured on a Windows GPU | ncnn's CPU-side steps are single-threaded without OpenMP. The Windows test laptop's integrated GPU is too slow for the AI tier, so it was refused there as designed; runbook §3.4 compares the speed on a faster GPU |
| On some Windows machines `doctor` lists one GPU twice | The Vulkan loader reports it twice; no functional effect ([Troubleshooting](../user/troubleshooting.md#doctor-lists-the-same-graphics-card-twice)) |
