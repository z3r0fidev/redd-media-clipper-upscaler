# rmedia 0.5.0 (feature 005 "Budgeted Reddit Video")

**Status:** Not yet released. Version 0.5.0 is set in the manifests; the tag `v0.5.0`, its
`release.yml` build and the GitHub release come after the
[owner check](../operations/fit-owner-checks.md) (SC-008, a real Reddit upload). Validation is
recorded in `specs/005-budgeted-reddit-video/checklists/validation.md`.

Commit range: `092171f` (tag `v0.4.0`) … (tag `v0.5.0`, to come); all 47 tasks of feature 005.

## Summary

`--fit` makes a Reddit-ready MP4 with sound that is **never larger than a size cap and never
longer than a length limit**. The caps come from video targets, data files like 003's GIF
targets: the built-in `reddit-video` has Reddit's limits (1 GiB, 15 minutes, 1920 px), verified
by a real upload on 2026-11-23, and your own files can set a subreddit's stricter rule. rmedia chooses the bitrate
from the length and the cap, measures the file before saving it, and encodes it again lower if
it is over. It works on `clip`, `upscale` (with 002's 9:16 and 4:5 presets) and `batch`, in JSON
and CSV manifests, and in the desktop app.

## New Features

- **`--fit TARGET`** on `clip`, `upscale` and `batch`, with `--fit-max-size`, `--fit-max-length`
  (overrides that can only lower a limit) and `--fit-allow-trim`. The output is H.264 High
  4:2:0 with AAC, fast-start MP4, cut frame-exactly (start and end ±1 frame, audio in sync)
  ([CLI Reference](../api/cli-reference.md#fit-a-reddit-video---fit)).
- **Two modes.** When the cap is the limit, two passes under a VBV ceiling use 95–99% of it
  (`budget`); when it is generous, one pass at CRF 20 under a quality ceiling, so short clips are
  not padded (`quality`).
- **Never over the cap.** The size is measured before the commit; an overshoot is encoded again
  lower, at most 3 times, and then the job fails (`FIT_FAILED`) with nothing written.
- **Limits.** A range over the length limit is refused (`RANGE_TOO_LONG`) or, with trimming,
  cut to it (`FIT_TRIMMED`). When the cap is too small, the picture size steps down (never below
  480 px on the short side, never enlarged) and then the audio; if that is still not enough, the
  clip is refused with the smallest cap that would work (`BUDGET_UNREACHABLE`) or trimmed to
  the longest start that fits. HDR sources are tone-mapped to SDR; frame rates above 60 are
  lowered.
- **Length in whole frames.** The output never lasts longer than the limit, container included:
  at 29.97 fps a 15-minute limit holds 26,973 frames (899.999 s).
- **Repeatable.** The same input, range and target give byte-identical files (each fit encode
  runs on one encoder thread; research R13).
- **Video targets as data.** `rmedia clip --list-fit-targets` (and `--json`); user targets in
  `<config>/video-targets/*.json`, validated, with problems listed by `doctor`
  ([File Formats](../api/file-formats.md#video-target-files-video-targetsjson)).
- **Dry run.** `--dry-run` predicts each job's size, bitrate and settings, for example
  `fit reddit-video: 1440x810 30 fps · video 1,440 kb/s + audio 128 kb/s (budget) · 4.9 MB of 5.0 MB`,
  and lists every encode pass with `-v`. The prediction was within 1% of the real size in
  validation.
- **Manifests.** A `fit` object at every level of a JSON manifest and the CSV columns `fit`,
  `fit_max_size`, `fit_max_length` and `fit_allow_trim`; `batch --fit` fits every clip
  ([File Formats](../api/file-formats.md#fit-in-manifests)).
- **Desktop app.** A **Video target** picker in the clip view, with custom limits, **Allow
  trimming** and a live prediction; refusals disable **Add clip**; the queue and the run panel show
  the cap and the result (`4.8 MB of 5.0 MB · trimmed`); **Settings › Targets** lists the targets
  and file problems ([Desktop App Guide](../user/desktop-guide.md#fit-a-reddit-video)).
- **`rmedia doctor`** reports `video targets: N (…)`, or `fit: unavailable — …` without
  `libx264` or `aac`.

## Enhancements

- JSON output, all additive: a `fit` block on planned jobs (with `pipeline` and `cwd`) and on
  outcomes, `fit_targets` documents, the stages `pass1`, `pass2`, `encode` and `verify`, and the
  `doctor` `fit` block ([JSON Output › Fit](../api/json-output.md#fit)).
- New issue codes: `RANGE_TOO_LONG`, `FIT_LOWERED`, `FIT_TRIMMED`, `FIT_FAILED`;
  `BUDGET_UNREACHABLE` gains `detail.min_cap` for fits.
- Name templates: `{target}` is the video target id in fit jobs.
- Desktop IPC: `list_fit_targets` and `fit_plan` ([Desktop IPC](../api/desktop-ipc.md)).
- **`reddit-post` GIF limit is 100 MB.** Real Reddit uploads found that post GIFs may be up to
  100 MB, not 20 MB. The built-in `reddit-post` target's hard limit is now 100 MB (the 8 MB aim is
  unchanged), and the target is marked verified (version 2). `reddit-video` is verified too
  (version 2; the owner's SC-008 upload). `reddit-comment` stays at 3 MB / 8 MB,
  unverified.

## Security

- **CSV export guards formulas.** A cell that starts with `=`, `+`, `-` or `@` is written with a
  leading `'`, so a spreadsheet does not run it; rmedia drops the `'` when reading, so exports
  read back unchanged ([File Formats › CSV Manifest](../api/file-formats.md#csv-manifest)).
- **User data folders.** Device presets, GIF targets and video targets load through one reader:
  at most 64 files (device presets had no cap), always the first 64 by name, and a file whose name
  has control or text-direction characters is skipped and reported with the name cleaned.

## Unchanged

Without `--fit`, every command behaves as in 0.4.0, apart from `reddit-post`'s hard limit above.
GIF export is otherwise unchanged, as is 003's silent Reddit MP4. Out of scope: uploading,
HEVC/AV1 output, and Reddit Premium's 30 minutes as a default (a user target can set it).

## Known Limits

- Reddit doesn't allow video posts in 18+ (NSFW, adult) or private communities; rmedia can't
  check where a file will be posted.
- `reddit-comment`'s GIF limits (3 MB / 8 MB) are still unverified.
- A trimmed clip keeps the default name of the range that was asked for, as GIF trims do.
- Fit encodes are single-threaded for repeatable output: 3 minutes of 1080p took about 4 minutes
  on the validation machine.
